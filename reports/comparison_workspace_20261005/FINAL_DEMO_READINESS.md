## 3–5 分钟建议现场顺序

会前完成依赖安装与构建。使用本分支 `.venv/Scripts/python.exe -m app.comparison_workspace_main`，
打开 `http://127.0.0.1:8765/`。不加 --enable-api。建议 1440×900 或 1280×800。
每次从新的“体验合成演示”项目开始，避免此前修订使固定叙述暂停。

| 时间 | 操作 | 要传达的内容 |
| --- | --- | --- |
| 0:00–0:30 | 首页 → 体验合成演示 | 三篇自制 PDF，全程无 Key；明确不是研究证据 |
| 0:30–1:10 | 展开一个结果下拉，查看矩阵报告结果和“允许差异” | 每篇有两个候选但只激活一个；92 / 89 / 91 是报告数字，背景条件仍可见 |
| 1:10–2:00 | 切换“相同协议”，先指出 STALE，再运行；看阻断与未决 | 随机 / 时间划分影响特定问题；B 的预处理未知没有覆盖这个阻断 |
| 2:00–2:45 | 点击 B 划分 → 提取文本 / PDF 第 2 页；固定 A/B 并排 | 解释可回到明确论文、页码与引文；文字出现不证明解释正确 |
| 2:45–3:10 | 关闭并排窗，切换“资源效率”并运行，看未决 | B/C 资源证据不足，系统不编造效率指标 |
| 3:10–4:20 | 回“相同协议”并运行，修订 blocker 解释并填理由，重跑；再换问题 | 用户修订保留；新问题下旧判断进入 STALE 历史区，不被当作当前结论。修订后固定 Demo 叙述暂停属预期 |
| 4:20–4:50 | 返回全部项目并重开，导出 Markdown；展示 JSON / CSV 选项 | 项目与修订持久化，产物可复核、可继续使用 |

时间紧时省略并排阅读或判断的第二次切换，保留“问题改变判断”和“回到原文”两个核心动作。
不要在第一次 5 分钟演示里现场安装依赖、配置 API 或处理未知复杂 PDF。

- “系统已经证明两篇论文科学可比 / A 方法更优”。

- “已定位 quote 意味着 AI 解释正确”或“用户修改自动成为已认证的人类 gold”。
- “这些合成数值属于真实实验、研究 benchmark 或有效性证据”。
- “真实 OpenAI API、所有 PDF、Ubuntu GitHub CI 已通过本轮验证”。
- “产品可用性证明研究新颖性、旧 MCA pilot 优越性或跨领域泛化”。

## 剩余限制

- OpenAI 仅 mock 测试，无 live 调用；需要真实账户 / 模型 / 费用验证时另行取得明确授权。
- 普通上传路径已用自制 PDF 验证；真实论文质量、复杂表格 / 公式、扫描件没有被全面验证。无 OCR。
- 一篇一个活动结果；本地单用户、单服务；未实现团队协作或旧数据批量迁移。
- 已知 fixture 新上传按原始字节 SHA256 识别，不是通用“合成内容检测”。演示使用新建项目。
- 过期手工判断须逐条复核；重新运行模型不会自动认可它们。旧目标的记录只供追溯。
- 手机可操作，但矩阵横向滚动、小字和证据长列表使阅读成本较高。演示优先桌面。
- 深度原提议审阅优先 JSON / Run API；当前运行弹窗只展示主要元信息。导出脱敏不识别所有私人内容。
- Linux GitHub CI 尚未执行；本地通过不代替远端 CI。15 个跳过测试不能计作已验证路径。
