## 1. 先说明本周做什么

- 本周目标不是扩展新功能，而是把已有 MVP 放进一次可追溯的团队协作流程。
- 重点包括统一 OpenAlex 真实样例、字段核查、检索词与人工判断、排序复核和 Git 协作规范。
- 当前稳定流程仍是获取、清洗、严格去重、初步排序、CSV/SQLite、图表和运行摘要；不包含 PDF 解析、RAG、知识图谱或多 Agent。

- 领域检索词：`docs/DOMAIN_QUERY_GUIDE_W1.md` 给出 5 个围绕恒星光谱分类、参数估计、降噪、异常检测和特征提取的查询方向。
- 人工标注：`data/manual/relevance_labels_w1.csv` 已提交，但当前有 1 行 CSV 格式异常且无法与统一样例 ID 对应，需要先修复和确认来源。
- 排序复核：`docs/RANKING_ANALYSIS_W1.md` 对统一样例前 20 名作人工复核，显示当前词项匹配和引用量因素会引入跨领域论文。
- 测试：根目录测试 CSV 和报告当前为空，不能作为已完成测试展示；项目负责人已完成一次 mock 回归验证。

## 4. 本周主要发现

- 100 条统一样例中，DOI 和摘要各缺失 4 条，来源缺失 2 条，落地页链接缺失 1 条。
- 不同检索词与词项语境会影响主题相关性；`power spectra`、`stellar masses` 等不是目标主题的语境仍可能得到较高相关性分。
- 在前 20 名人工复核中，成员记录了 5 条不相关、2 条部分相关和 2 条边界案例；这是人工判断，不是全样例准确率。
- `preliminary_score` 只能用于初筛，不可解释为论文真实学术价值。
- 当前 Git 协作说明内容完整，但明确不包含 Python 环境复现；汇报时不要把两者混为一项成果。
